# CV exports

The resume lives at `/cv` and `/ru/cv`. Everything downloadable is generated
from it, so there is exactly one place to edit: `src/data/cv.ts`.

```
src/data/cv.ts                 canon, RU + EN, typed
  ├── /cv, /ru/cv              the page (src/components/CvDocument.astro)
  ├── /cv.txt, /ru/cv.txt      plain text, rendered by an Astro route
  └── public/cv/*.pdf|docx     generated by build-exports.ts
```

`src/lib/cv-text.ts` turns the canon into a flat node list that the txt route
and the DOCX builder both consume, which is why the two cannot drift.

## Regenerate

Requires Google Chrome (or Chromium) and a prior `npm run build`.

```bash
npm run build && npm run cv:export
```

Writes `Mikhail_Semenov_CV_{EN,RU}.{pdf,docx,txt}` into `public/cv/`.
Commit the regenerated files together with the content change.

The PDF is printed from the real page through `src/styles/print.css`, so a
visitor pressing Cmd+P gets the same document as the Download PDF button.

## The variant with the phone number

```bash
npm run cv:export -- --phone "+7 900 000-00-00"
```

Writes into `private-exports/`, which is git-ignored. Use these files for ATS
forms; use the public ones for anything that touches the site.

The number never enters the repository. Git history on a public repo is
permanent, so a number committed once is public forever. This run builds the
site into a git-ignored `dist-private/` with `CV_PHONE` set, prints from it,
and deletes it. **Never set `CV_PHONE` in CI** — a test asserts that no
phone-shaped string reaches `dist/`.

## Things that were learned the hard way

Each of these silently broke the file that recruiters and parsers actually
read, so the print stylesheet keeps a comment at every one of them:

- **A decorative blend mode cost 9 MB.** `body::after` paints a film-grain
  texture with `mix-blend-mode`. Chrome cannot express that in PDF vector
  operators, so it rasterized every sheet: the resume came out at 9.2 MB,
  large enough for mail servers to strip. Disabling it in print took the file
  to under 300 KB.
- **A two-column grid scrambled the text layer.** The metric tiles read out of
  `pdftotext` as `~10% / ~80 / share held by... / repeat payments...`, every
  value divorced from its label. An ATS reads that same stream. The tiles are
  single-column and inline on paper.
- **Letter-spacing split the headings.** `SUMMARY` came out as `S U MMARY`,
  `NUMBERS` as `N U MBE RS`. An ATS looking for a SUMMARY section found none.
- **Chrome defaults to US Letter**, which is the wrong sheet for every market
  this resume targets. `@page { size: A4 }` is explicit.
- **`break-inside: avoid` on a role emptied a page.** The Zvonobot block is
  longer than a sheet, so keeping it whole pushed all of it forward and left
  40% of page one blank. Only bullets and cards are kept whole now.
- **Hyphens vanish at line breaks.** A wrapped `+7 982 230-60-19` came out of
  the text layer as `+7 982 230-6019`. The number is `white-space: nowrap`
  now. The same still happens to `full-time` in the EN summary when it wraps,
  which is one more reason DOCX is the better upload for an ATS form: there
  the word is intact.

Check any regenerated PDF with `pdftotext file.pdf - | head -40` before
sending it anywhere. `tests/cv.test.ts` covers the rest.
